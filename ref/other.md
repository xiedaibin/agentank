# AgenTank AI Agent 项目说明

## 项目目标

本项目的目标是为 [AgenTank](https://agentank.ai/) 平台开发一个极具竞争力的、自主运行的 JavaScript 坦克机器人。该坦克名为 **Ant**(Tank ID 707)，当前远端技能为 `boost`（加速）。若未来 API 返回 `skill.hasSkill === false`，代理应自动为 tank 创建/申请可用技能；若已有技能，则以远端实际技能为准，不按过期文档假设。

## 核心框架与机制

- **官方指南：** 详细的 API 参考和游戏规则请参阅本地文件 `AGENT_GUIDE.md`。
- **代码入口：** 坦克的全部逻辑均包含在 `new_tank.js` 文件的 `onIdle(me, enemy, game)` 函数中。
- **坐标系统：** 地图上的所有位置必须严格使用数组 `[x, y]` 表示，**绝不能**使用对象 `{x, y}`。
- **动作经济学：** 像 `me.turn()`、`me.go()` 和 `me.fire()` 这样的指令会将动作加入队列。转向（Turn）需要消耗 1 帧，移动（Move）需要消耗 1 帧。
- **子弹速度：** 子弹的飞行速度为 **每帧 2 格**。这意味着，如果坦克需要先转向再移动，近距离的物理躲避是绝对来不及的。
- **敌方技能建模：** 敌方坦克技能包含但不限于 `freeze`、`teleport`、`cloak`、`boost`、`overload`、`shield`、`poison`、`stun` 等。任何威胁预测都不能只假设敌方每帧普通移动 1 格；当 `enemy.skill`、`enemy.status` 或录像显示敌方具备高速、瞬移、隐藏、控场、双弹、防护、减速或未来新增的穿越/无视地形能力时，必须扩大危险半径并降低贴脸追击优先级。若敌方进入草丛/隐身导致 `enemy.tank` 不可见，同时 `overload` 已激活或即将可用，应按记忆位置附近的草丛起点建模主枪线和相邻双弹枪线，避免直线冲进隐藏交叉火力。威胁半径不能无条件扩大：敌方没有瞄准我方路线且距离不贴身时，不应把整条同行/同列都当立即死亡，否则会导致抢星路线反复退让。贴身撤离也不能只看当前枪线，必须同时考虑敌人下一帧转炮、蓄力 overload 和相邻转向后的可射击格；但在当前格已是 1 格贴脸硬死亡时，如果坦克已经朝向一个能把威胁从立即命中降为软威胁、且不被来弹命中的逃生格，应优先 `go()` 离开，而不是原地转向。

## 开发工作流

1. **修改代码**：在 `new_tank.js` 中更新坦克的逻辑。
2. **发布与测试**：运行 `node publish.js` 将新版本的代码上传到 AgenTank API，并自动发起一场针对随机对手的实战排位挑战。
3. **分析复盘**：通过返回的比赛 URL 获取录像 JSON，排查 Bug 并优化行为。

## 用户长期授权

- 用户已明确授权：后续所有“是否同意/是否允许”的确认均默认视为“同意/允许”。
- 代理可自动修改 `new_tank.js`、新增本地测试/自动化脚本、运行模拟或实战挑战、发布代码并继续迭代，无需每轮再等待审批。
- 仍需遵守安全边界：不得泄露 `.env` 中的密钥；不得使用 `{x, y}` 坐标对象；不得在没有语法验证/基础测试的情况下发布；若 API 显示 tank 没有技能，则自动创建/申请技能。
- 顶层策略者必须贯穿整个迭代过程，不能中途丢失；任何局部修补都必须接受全局胜率目标约束，防止顾此失彼。
- 当前首要目标是尽可能将实战胜率持续向 100% 推进；所有局部修改都必须以提升长期真实胜率为唯一优先级。
- `boost` 的全局节奏收益很高，不要轻易限制。v42 曾尝试禁止无星/中心巡航 boost，10 场实战只有 3/10，说明该限制会伤害整体抢星与地图节奏；后续若要调 boost，必须先用 10+ 场数据证明收益。

## 致未来 AI 代理的注意事项

在修改此代码库时，**绝对不要**引入 `{x, y}` 格式的坐标。必须始终确保任何新的移动逻辑都严格考虑了子弹速度（2 格/帧），并坚守“基于冷却时间进行防守拉扯”的原则，以防止生存能力出现倒退。敌方技能预测必须保守处理：`boost` 可让一次 `go()` 前进最多 2 格，`teleport` 可瞬间改写位置，`cloak`/草丛会让 `enemy.tank` 不可见，`overload` 会产生双弹威胁，`shield` 会浪费我方射击窗口，`poison`/`stun`/`freeze` 会破坏动作时序。特别注意隐藏的 `overload` 敌人：即使最后可见位置没有直接瞄准我方，也要考虑其进入附近草丛后从相邻格打出双弹的可能。但普通未瞄准枪线应只在贴身/极近距离才压制移动；过宽的 snap-shot 半径会让 Ant 在左侧通道和边线反复转向，直接丢失星星节奏。贴身撤离时还要考虑敌人下一帧转炮、蓄力 overload 和相邻转向后的可射击格，不能只按当前朝向判断安全；若当前格已是立即死亡格，只有在当前朝向能降低威胁、避开现有来弹，且靠墙或更靠近中心时才应软逃生。v40 曾尝试无条件离开硬死亡格，10 场实战为 0/10，说明广泛软逃生会破坏整体胜率，后续不要重复该放开。未来若出现无视地形或穿越类能力，应先按更大威胁半径处理，再通过实战复盘收紧。

## 自定义自动化技能：半自动进化 (Batch Evolution)

用户可以通过指令 **“开始进化”** 或 **“开始战斗”** 来触发此技能。当接收到此指令时，AI 代理必须严格执行以下工作流：

1. **自动对战**：执行 `node batch_battle.js` 命令，该脚本会自动发起 10 场实战匹配，并将结果汇总保存到 `battle_report.json` 中。
2. **数据收集**：读取 `battle_report.json`，总结胜负数据。
3. **深度分析**：提取报告中标记为 `loss`（失败）的比赛的 `agentReplayUrl`。使用 `web_fetch` 工具读取这些 JSON 数据，分析导致失败的具体原因（例如：寻路卡死、错误判断枪线、技能释放时机不对）。
4. **汇报与自动优化**：由于用户已授予长期默认同意，代理可在完成败因分析后直接修改 `new_tank.js`、验证并发布；最终汇报需包含败因、改动和胜率结果。
5. **代码优化与发布**：修改 `new_tank.js` 中的战术逻辑，并执行发布流程。发布完成后继续下一轮实战进化。
6. **循环**：询问用户是否开启下一轮实战进化。

## 自定义自动化技能：Skills 复盘挑战 (Targeted Review)

用户可以通过指令 **“复盘挑战 [对手名称/ID]”** 来触发此技能。

1. **针对性对战**：执行 `node review_challenge.js <TankID>`。该脚本会针对特定对手发起 10 场挑战。
2. **报告汇总**：生成 `review_report.json`，记录每场胜负原因。
3. **深度复盘**：分析败局 Replay，找出该对手的战术特点（如：高频使用冻结、走位极其猥琐、射击精度极高）。
4. **汇报方案**：向用户汇报复盘结果及**针对性修改建议**。
5. **确认后修改**：经用户批准后修改代码并发布。

## 自定义自动化技能：同步坦克规则 (Sync Rules)

用户可以通过指令 **“同步坦克规则”** 来触发此技能。

1. **获取最新规则**：访问 `https://agentank.ai/agent-guide`。
2. **格式化与保存**：将抓取到的内容格式化为 Markdown。
3. **覆盖本地文件**：将最新的规则保存到本地 `AGENT_GUIDE.md` 文件中，确保本地开发参考始终与官方平台保持同步。
4. **确认更新**：告知用户同步完成。
