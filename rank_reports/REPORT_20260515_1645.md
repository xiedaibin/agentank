## 一、 核心矛盾分析 (Primary Contradiction)
通过对 122 场败局摘要及 `new_tank.js` 源代码的深度审计，发现限制胜率突破 60% 的**头号杀手**是：
### **“无效死亡”与“超时死亡” (Death Reason: Timeout/Other)**
在摘要数据中，几乎 100% 的败局被判定为 `Timeout/Other`。结合 `new_tank.js` 的 `onIdle` 逻辑，这揭示了一个重大算法缺陷：**坦克在被击毁前的判定逻辑失效，或者在死角/枪线计算中出现了严重的“逻辑僵死”。**

**具体表现**：
1. **防御逻辑单一**：`tacticalDefense` 仅在检测到 `enemyBullet` 且 `framesToHit <= 3` 时触发。对于高分段对手，这属于“临终抢救”，往往因为转向耗时（1帧）导致避弹失败。
2. **缺乏“预判性防御”**：目前代码对“枪线（LoS）”的反应仅限于 `isSafe` 里的静态判定，没有考虑到敌方坦克的转向意图。

## 二、 战术共性总结 (Tactical Patterns)

### 1. 传送后的“僵直脆弱期” (Post-Teleport Vulnerability)
*   **现象**：`G_History.postTeleportFrames = 8`。在传送落地后的 8 帧内，坦克虽然有逻辑，但由于 `evalAssassination` 缺乏对降落点瞬间环境的极限压缩判定，经常在落地瞬间被对手守株待兔。
*   **原因**：传送落点 `findAssassinSpot` 仅检查了 `isSafe`，但 `isSafe` 对子弹的判定是滞后的。

### 2. A* 寻路的“墙角陷阱” (Corner Trap)
*   **现象**：大量败局发生在地图边缘。
*   **原因**：`evalSurvival` 只是简单地将坦克推向中心点（Center），而在撤退过程中，如果 A* 认为路径不安全，会切换到“盲趋”逻辑，这在复杂地形下会导致坦克在墙角反复抖动（Oscillation），最终被远程狙击。

## 三、 算法改进建议 (Algorithmic Improvements)

### 1. 升级防御频率（主要矛盾解决方案）
**修改建议**：将避弹判定从 `framesToHit <= 3` 提升至基于距离的动态判定。
*   **逻辑**：如果敌方正对着我且距离 < 10，即使没开火，也应视为“准危险状态”，增加横移权重。

### 2. 传送落点二次校验
**修改建议**：在 `teleport` 之前，模拟落地后的第一帧敌方可能的反击。
```javascript
// 建议新增逻辑片段
if (ctx.canTeleport) {
    // 增加对落点周围 2 格的“未来枪线”扫描
    if (isUnderPredictiveFire(spot, ctx)) return null; 
}
```

### 3. 引入“死亡倒计时”强行传送
**修改建议**：当检测到避无可避的子弹（Dodge 失败）时，目前的 `findEscapeSpot` 偏移量过小（4格）。在高分段，应增加随机大范围跳跃，以破坏对手的连击。
